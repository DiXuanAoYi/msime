# 语音工作台与模型参数

设置 → 语音 →「语音发送 / 语音转方言」，或在嘴替草稿、备选回复旁点击「转成语音」。转入工作台不会自动生成或发送。

## 使用

1. 在发音设置中启动已下载的模型。当前模型的音色、语言和可用参数会出现在工作台中。
2. 输入文字，或录音 / 导入音频，再点击「本地识别成文字」。此识别入口只使用已配置、已启动的本地 ASR，不调用云端润色。
3. 检查识别文字，选择音色、语言、语速及本次参数，点击「生成并试听」。支持流式的本地模型边生成边播放。
4. 「复制音频文件」后，可在支持文件粘贴的聊天窗口中粘贴并手动发送；也可「另存为 WAV」。编辑内容后必须重新生成，不能误用之前的音频。

输入音频限 32 MB、90 秒，生成文字限 2000 UTF-8 字节。原始录音只保存在工作台内存中；生成的 WAV 位于用户数据目录的 `voice-outbox`，升级与更换数据目录均保留。关闭设置会取消工作台任务并停止录音。

## 原生语音消息

工作台可将生成结果输出到用户选择的虚拟音频设备，例如 [VB-Cable](https://vb-audio.com/Cable/)。先自行安装、配置虚拟音频设备，并在聊天软件中选择对应的录音设备；点击「3 秒后输出到虚拟麦克风」，切回聊天软件开始录音，结束和发送均由用户操作。

不会安装驱动、改变 Windows 默认音频设备、操作联系人或自动按发送键。没有虚拟设备时按钮不可用；聊天客户端不提供录音入口时使用音频文件方式。不同客户端对录音设备、消息时长和文件附件的支持不同。

## 音色、方言与参数

- Qwen3-TTS 0.6B / 1.7B：9 个官方预设音色；Dylan 为北京话，Eric 为四川话。采样、重复惩罚、长度、流式分块可调；只有 1.7B 提供指令控制，0.6B 不显示无效指令项。
- MOSS-TTS-Nano：18 个随模型提供的参考音色，Zhiming 标注京味参考音色，实际效果请试听。调节采样参数时自动切到能应用这些参数的完整采样路径，可能比固定快速采样慢。
- Kokoro：保留常用音色别名，另外提供当前模型包的 0–102 号音色，不为未验证的编号编造姓名或方言。
- Edge-TTS：提供服务实际返回的音色列表，标注粤语、东北话、陕西话等；这是在线服务客户端，必须用户主动选择，不作为离线默认。
- Voxtral TTS：20 个预设音色，支持英语、法语、西班牙语、德语、意大利语、葡萄牙语、荷兰语、阿拉伯语和印地语；不支持中文方言。

方言生成是「本地识别 → 可编辑文字 → 模型实际支持的目标音色」；不承诺保留原说话人声音，不把普通变声标成方言翻译。设置页参数按模型保存；工作台参数只影响本次生成。

## Voxtral 与 FlashTTS

[Voxtral 官方权重](https://modelscope.cn/models/mistralai/Voxtral-4B-TTS-2603) 的固定清单为 24 个文件、8,037,629,039 字节，设置页显示下载大小。用户点击下载才拉取，逐文件验证 SHA-256。首次点击启动时在本机转换 Q8 权重，建议至少 16 GB 内存、26 GB 可用磁盘，首次转换较慢。Windows 适配采用固定版本的 audio.cpp CPU 后端，原生回调实时交付 PCM；没有宣称在 6 GB 独显上运行该模型。模型许可证为 CC BY-NC 4.0。

[FlashTTS 2026](https://github.com/ASLP-lab/FlashTTS) 暂无可核实的官方权重链接；界面显示「等待官方权重」，不提供会失败的下载、启动按钮。用户确认先完成其余功能。

本次没有自动下载任何新模型权重。Voxtral 已完成下载清单、断点续传、校验、原生 ABI、无模型错误和流式接口测试；因未下载权重，完整模型转换、实际音质和首声延迟尚未实测。原生聊天语音仍需在安装虚拟设备且支持录音的客户端上验证。

## 构建

在打包 Python 运行时前执行 `scripts/local_asr/Build-Voxtral.ps1`，它固定下载、编译 Apache-2.0 的 audio.cpp 源码，不下载模型。随后运行 `Build-Runtime.ps1`；发布工作流已包含这两步。生成的 DLL、转换工具和许可证随安装包分发，模型单独按需下载。
