## 本次调整的主要决策

1. 采用 v0.10.1 最终输入与界面行为：Emoji 首页末位保留一个最相关结果；默认输入法按中文键盘列表排序；语言按钮支持三语循环。v0.10.0 对应的旧方案不再单独实现。
2. 借鉴 v0.10.1 的旧设置和有效效果模型迁移修复（#852），保留自定义或校验未通过的旧文件，再接入发布后的旧候选翻译开关保留修复（#884）。不采用 v0.10.0 清除旧效果模型、要求重新下载的升级行为。
3. 八股文单次加成、AI 翻译统一提供方、纯简拼保护属于发布后修复。它们分别评审依赖、配置迁移和排序回归，不写成 v0.10.1 Release 已包含。
4. 912,640 条中译英数据与青简 11 类领域输入数据分层处理。词库源文件、构建脚本和最终安装包中的数据各有独立校验，不能仅凭 Release 文案认定数据已随包生效。
5. 英文候选的设置和后台更新尽量即时生效；TSF DLL 本身的更新仍需相关宿主加载新 DLL。界面分别显示后台版本、宿主版本与能力，避免要求用户为普通开关修改重开应用。
6. 本地拼音整句、文本续写补全和问字使用不同任务及结果合同。保留已有模板内容，通过明确的执行方式接入，而不只替换提示词。

### 移植时必须保留的扩展接点

上游本来没有本分支的大量扩展，整文件替换会移除有效功能。下列文件按功能差异合并，并以当前分支的调用链作为保留依据：

- `server/CMakeLists.txt` 保留语音工作台、候选发音、个人资料库、Vision、ASR/TTS/OCR 运行组件、聊天读取与生词统计的源文件和目标。
- 工具栏 presenter、宿主和 HTML 保留语音、嘴替、剪贴板三个入口及尺寸计算；仅接入阴影、跨屏放置和三语切换相关改动。
- 候选模板和两种 presenter 保留 Ctrl 点击中英文发音、带调拼音及其开关、翻译详情和来源标签，防止新版布局或切分覆盖现有事件。
- 设置宿主、共享分发、`config-sync.ts` 和出厂模板保留本分支所有配置字段；尤其保留完整 appearance 快照传递及拼音开关反复开关回归。
- 安装器保留输入法自身模型服务停止、模型缓存与聊天数据保留、个人字典来源和打包校验；不采用上游仅适用于其原始功能集合的文件删除清单。
- IPC、按键和选词改动保留新版上屏撤销、宿主 PID 验证、软件学习隔离、提交确认及生词统计能力；合并新能力前核对字段、opcode 和 capability 分配。

正式删除旧代码之前，要求能从页面动作追到实际宿主、配置写入和回读；没有证明为无调用代码的本分支扩展不删除。

## 升级与运行时兼容

### 配置和数据保留

升级保留现有设置、个人词库、软件独立学习、生词统计、模板 ID 与正文、剪贴板分组、语音收藏及草稿、已下载模型和聊天上下文。新安装默认值与升级迁移分别测试；新增开关不会把老用户已有值翻回新默认。

API 凭据加密按统一凭据字段清单扩展至 AI、翻译、ASR、TTS、OCR 和按厂商保存的槽位。旧明文迁移须原子落盘，失败保留可恢复的旧配置；密文解不开时提示重新配置，不能把密文本身发往厂商。配置复制至其他 Windows 账户或机器、降级到旧版的凭据处理也需明确。导出模板和普通资料默认不带凭据。

上游 `IsCredentialKey` 的字段白名单未覆盖本分支的 `azure_key`、`elevenlabs_key`、`tencent_secret_key`、`shiliu_appcode`、`baidu_api_key` 等字段，不能直接复制后宣称所有 API 已加密。已有聊天上下文加密继续保留，API 配置与聊天记录的保护分别验收。

模型目录迁移先校验旧文件，再迁至新目录或保留旧路径回读；目标已有有效模型时不得覆盖。只停止输入法自己的模型服务与工作进程，保持现有按路径识别的进程停止逻辑，不结束无关 Python 进程或聊天软件。

### 英文候选即时生效

青简在会话开启、模式同步和重连时下发按宿主计算的运行时设置，并热加载后台配置。它的安装器同时说明旧应用保持旧 DLL，直到退出重开。[青简模式同步](https://github.com/qingjian-team/qingjian/blob/dd9c471766e117c1f8c557042560776179fe9bfe/apps/windows/tsf/src/com/service/mode.rs)、[青简安装器](https://github.com/qingjian-team/qingjian/blob/dd9c471766e117c1f8c557042560776179fe9bfe/apps/windows/installer/qingjian.iss#L10-L16)。

水杉保留已有英文首键拦截、后台查询和焦点代次保护，新增以下能力：

- 正式区分英文状态候选总开关与中文混输英文开关；每软件可继承、开启或关闭。
- 在共享 IPC 合同中定义带 revision 的可选运行时设置能力。激活、重连先给快照，变化通知后刷新，丢通知有恢复路径。
- 禁用候选时安全结束当前 composition，取消过期查询；重新启用后下一首键生效。
- 在诊断界面显示当前宿主实际 DLL 版本、路径和已协商能力。只在需要新 DLL 代码时提示完整退出相关软件。
- 旧 DLL 与新 Server、新 DLL 与旧 Server 都有明确协商和降级行为。后台不可用时保留正常输入与快捷键，不强制热卸载已加载 DLL。

不直接复制青简的 Rust 状态机或协议枚举；沿用水杉 `engine/contracts/` 的唯一合同来源及现有 capability 协商。

### 敏感字段与上下文边界

密码与 PIN 保护完整接通 TSF 字段识别、IPC 标志、Server 请求及学习历史门禁。上游读取 InputScope 失败时按普通字段处理，不能把它当成所有密码框均受保护的证明。本分支规划采用普通、敏感、未知三态；读取失败、没有可靠声明或旧 DLL 未提供能力时按未知处理，抑制自动云 AI 请求，基础输入与快捷键正常使用。

自动输入上下文绑定 client、输入框和 activation epoch，切换后清空临时前文。疑似凭据过滤只作用于发送副本；它不能识别所有密码、纯数字 PIN 或私人信息，不替代字段门禁。每人和每群的持久聊天上下文继续由原功能管理，不因清理输入前文而删除。

## 输入正确性与性能

先移植 v0.10.0 的已选前缀标点提交、混合简拼优先、声母加完整拼音保护、日语转换排序和 `nn` 处理，再移植 v0.10.1 的合法全拼回溯切分、等音节歧义裁决与模糊音词频混排。查询、预编辑和选词消耗必须使用一致的切分，避免候选正确但继续输入时吞字。

按 v0.10.1 的最终语义接入默认输入法、语言按钮、任务栏图标和 Emoji 位置。新增可选中日英循环、默认关闭的 Vim 按软件白名单和五笔两开关；Caps Lock 标点与 Shift+Enter 使用对应按键策略，不虚设上游没有的独立开关。新增问字入口不抢占 Unicode、计算器或临时日语。

神经打分在大于四行时采用八行权重复用，保留一行、两行及不超过四行的专用分支、CPU 能力探测与标量回退。用相同候选、同一模型、同一机器比较冷启动、温态和 P50/P95。上游的 30.1 ms 与 22.8 ms 是其特定评测数据，不作为本机已达到的成绩。[AVX2 实现](https://github.com/metasequoiaime/msime-windows/blob/0d7ae4ca795708261c354316e9f0554a9cbc35d6/engine/neural/int8_linear_avx2.cpp)。

八股文修复另行移植：加成只注入一次，统一量纲与参数，同时给旧高级配置提供迁移解释。普通候选与按键提交不等待模型、网络或文件导出；不能通过扩大 TSF 提交超时掩盖卡顿。

这是已安装基础输入库的静态词形比对；已有词形不等于读音、召回和排序均与青简一致。原始 11 个 TSV 共 4,522,407 字节，字段为词形、无声调拼音、词频；另一个 `domain_words.tsv` 为 462 条，字段顺序不同，转换器必须分开解析。

全部领域库随包加入独立输入数据文件，不写入用户词库。保存包 ID、原词形、拼音、权重、来源提交、许可与摘要，按“词形加读音”去重，保留跨来源归属。接入全拼、双拼、简拼和整句词图，避免只在 Server 最后临时插入几条词。

词库页将“输入领域词库”“离线释义词典”“个人及软件词库”分区展示。每库有独立开关、搜索、原始及有效条数、来源和导出。每软件可继承全局集合或指定集合；关闭一个包只取消该包贡献，基础库已有同词仍可出现。新增专业库默认关闭，成语建议开启；已有用户的开关原样保留。

候选标签可选显示领域，详情展示完整来源和读音。原 TSV 没有声调；带调标注需词级读音数据校验，不能用逐字猜测承诺多音地名或人名读音正确。

转换与分发保留青简的 THUOCL、Unihan 和词频加工说明。[青简来源声明](https://github.com/qingjian-team/qingjian/blob/dd9c471766e117c1f8c557042560776179fe9bfe/tools/dict-convert/src/lexicon/mod.rs#L66-L70)、[THUOCL MIT](https://github.com/thunlp/THUOCL/blob/master/LICENSE)、[Unicode License V3](https://www.unicode.org/license.txt)。

### 上游中译英数据与既有翻译词库

v0.10.0 的 Release 声称新增 912,640 条释义，但两个冻结标签的 `product-lock.json` 仍指向相同的 `dict-v1.0.0` 和 `english.db` 摘要；其 Release 流水线仍下载锁定产物，没有调用新增的源数据构建器。因此，这个条数不能作为已核实的官方安装包或本分支安装数据条数。下一轮明确选择并固定包含新释义的输入，执行源构建、产物计数和实际安装查询。[冻结产品锁](https://github.com/metasequoiaime/msime-windows/blob/0b39cbfa2752ab9724a241c6b05cf13d1e00f4d2/product-lock.json)、[冻结发行流程](https://github.com/metasequoiaime/msime-windows/blob/0b39cbfa2752ab9724a241c6b05cf13d1e00f4d2/.github/workflows/release.yml)。

本机现有锁定 `english.db` 与上述摘要相符，其中 `zh_en_glosses` 为 31,371 条、`en_zh_glosses` 为 91,057 条；这只描述基础文件，不包含本分支已经另加的青简和行业释义层。本轮未拆解官方 EXE，不能由流水线检查反推所有官方二进制的实际内容。

新释义作为新增数据层，保留全部原始词性、义项和来源。当前自定义翻译仍有最高优先级，不用上游构建器的替换语句覆盖个人数据或丢掉其他来源。

候选摘要与完整数据分别处理：摘要可紧凑显示、展开查看全部；详情、发音选择和导出读取完整义项。Ctrl+Enter 上屏只移除展示用的词性与读音，不改原始记录。词性和分隔符分别适配深浅主题、选中行、D2D 与 WebView2。

当前跨来源合并最多保留六个不同义项，完整子页链路并不代表所有来源的全部内容都已传到页面。下一轮保留完整来源记录，再产生展示摘要；生词曝光仍只统计实际展示的译词，不把隐藏详情计为已经看过。

补齐泰语、意大利语等界面与厂商映射；越南语已有本地层则复用。服务支持某语言不代表本地词库已有该语言。新的默认厂商只影响新安装且联网明确可选；升级保持当前选择及离线开关。

发布后的 `translation.provider` 枚举用于候选在线翻译，迁移仍受本分支已有在线补全开关约束；本地数据优先级保持不变。截图、对话和字幕工作台的翻译选择有独立用途，不将它们已有的 `translation_provider` 字段误当成同一配置直接覆盖。连接资料可共享，功能选择和上下文范围分别保存。

字典构建和发行分别固定输入版本、产物摘要、数据条数与许可。安装后抽查每个数据层的实际查询，构建脚本存在不能替代最终包验证。

## 本地整句模型与 AI 模板

| 任务 | 执行方式 | 候选行为 |
|---|---|---|
| 拼音整句重排 | 水杉既有词格、Google 解码器、速度和效果神经模型 | 对既有句子排序，保留用户已选前缀 |
| 拼音整句生成 | 可选含章通变适配 | 词格缺完整句时生成补充结果，明确支持的输入方案 |
| 文本续写补全 | 用户已有本机文本模型服务，或主动选择的云 API | 单独显示补全行，接受时不重复前文 |
| 问字 | 本地查字数据、具备问答能力的本机服务或可选云 API | 显示答案、读音和来源，由用户选择 |

AI 辅助页按任务选择执行方式，再选择模型或模板。原有自定义模板 ID、正文、名称和选择状态保留。新增聊天续写、工作消息、邮件、汇报、学习笔记、代码注释等模板；添加、删除、导出、导入和自动保存复用现有模板库。重排模型不能执行自由提示词，界面应显示它真实支持的参数。

水杉已有模型为 `sentence-model.safetensors`（4,486,280 字节）和 `sentence-model-desktop.safetensors`（25,480,184 字节）。借鉴上游效果档按需下载、浏览器下载、导入、删除和状态查询，扩展显示大小、摘要、来源和实际运行状态；旧文件迁移后继续使用，不自动重下。[模型清单](https://github.com/metasequoiaime/msime-windows/blob/0b39cbfa2752ab9724a241c6b05cf13d1e00f4d2/neural-model/lock.json)。

含章通变与知微采用 GPL-3.0-or-later，`.qjm` 与水杉当前加载格式不同，需要专门适配。通变以拼音为条件，当前直接生成主要覆盖全拼；双拼先使用现有重排，转换适配验证后才开放生成。先证明 Windows 推理与错误回退可运行，再将模型标为可用。[青简模型格式](https://github.com/qingjian-team/qingjian/blob/dd9c471766e117c1f8c557042560776179fe9bfe/crates/qingjian-neural/src/qjm.rs)、[生成条件](https://github.com/qingjian-team/qingjian/blob/dd9c471766e117c1f8c557042560776179fe9bfe/crates/qingjian-core/src/engine/query/generating.rs)。

现行含章两款模型的单文件大小尚需从官方清单或包目录核实；不将 `data-v6` 综合数据包的 143,814,324 字节冒充单模型大小。模型下载须用户主动操作，下载或导入后校验、原子落位；普通设置刷新不触发模型下载。

## 整句补全与问字交互

### 整句补全

青简的整句补全使用 `Compose.want_sentence` 请求和独立 `sentence` 结果；含章的推理前缀缓存不构成自由文本续写能力。[青简提示词合同](https://github.com/qingjian-team/qingjian/blob/dd9c471766e117c1f8c557042560776179fe9bfe/crates/qingjian-predict/src/prompt.rs)。

水杉新增明确的补全结果类型，绑定应用、输入框、当前文本和请求代次。仅使用获准的光标前文或本次会话前文；密码与 PIN 输入禁用，切应用清空临时输入上下文，保留独立管理的聊天历史文件。

候选立即显示，停顿后异步补全。模型失败不妨碍打字；翻页、移动高亮、继续输入、切焦点或关闭功能后，旧结果不得覆盖当前页面。接受键可配置；Tab 只在明确显示可接受补全时处理，否则保持原行为。选择只上屏，不发送聊天消息。

### 问字

等价接入青简的自然语言拼音问字，例如“三个木是什么字”返回“森 sēn”，“三个直怎么读”返回“矗 chù”。输出使用独立答案结构，多答案可选择；过滤模型复述问题的无效结果，不带应用上下文。[青简问字分流](https://github.com/qingjian-team/qingjian/blob/dd9c471766e117c1f8c557042560776179fe9bfe/crates/qingjian-core/src/engine/prediction/mod.rs#L77-L95)。

入口包括工具栏按钮、可配置快捷键和用户选择的问字前缀。保留 U 的 Unicode 查询、V 的计算器、R 的临时日语；双拼入口不占用音节键，普通问号默认仍是标点。

答案支持读音、发音、复制及手动上屏。已知字音优先核对词典，多音字展示可选读法；离线拆字和部件反查作为辅助。复杂问答需要支持该任务的本机文本模型或用户启用的云 API，含章通变和知微不提供通用问答。提问内容不作为答案的拼音学习键写入用户词库。

## 设置界面与发行流程

本分支已有 AI、语音和翻译的连接测试，继续复用。新增的是模型列表查询、可手填模型的下拉、Custom 独立槽位与 DeepSeek 思考强度，均适配现有模板库和页面布局。模型列表请求只获取名称，不下载权重；连接测试成功不等于补全质量、JSON 输出或思考参数已经验证。思考参数仅在厂商支持时显示，AI 联想和语音润色分别保存，低延迟联想默认关闭长时间推理；用户显式保存的设置继续保留。

候选宽度收紧覆盖拼音标注、完整翻译、来源标签和翻页箭头；工具栏阴影及跨屏放置保持已有语音、嘴替、剪贴板入口。新增控件复用深浅主题、焦点、禁用、展开列表和键盘导航规则，检查实际窗口尺寸与 DPI。

当前关于页读取 `https://msime.app/update.json`，再按数值版本判断更新，且校验器只接受官方仓库地址。这会把个人分支用户引导到官方安装包下载页，尚不会自动安装，但可能在用户确认后覆盖个人扩展。

更新检查以仓库、产品身份、频道和版本共同判断，目标为 `DiXuanAoYi/msime`；现有 `chat` 发布为 prerelease，不能只改成 `/releases/latest`（本次读取该接口返回 404）。明确支持选定的预发布频道、正确源码 tag、安装资产与摘要，官方上游信息可单独展示。

官方镜像模式硬编码了上游仓库；本次对个人分支资产构造的镜像地址返回 403。镜像按钮只在支持与摘要校验通过后启用，保留 GitHub 直链。默认输入法操作只由用户点击执行。

VC++ 和 WebView2 的安装提示经用户同意打开官方下载直链，由用户完成安装并重新检测；本地构建入口另准备 pnpm、pypinyin 等所需开发依赖。这不代表安装器已经自动安装所有运行组件或开发环境，模型权重始终按需下载。

检测缺少 WebView2 Runtime 时，本进程候选临时降级 D2D，保留用户原后端选择；其他环境或 controller 创建失败给出阶段及 HRESULT 说明。更广的创建失败自动切换若要扩展，需要独立状态和回归设计，不能当成上游已解决。

SignPath 和 GitHub 托管 runner 作为可选发行工作：个人仓库需自身的服务申请、凭据与签名配置，不能继承上游签名资格。未配置时继续明确标为未签名包，不宣称 uiAccess 生效。构建缓存失效可退回 MSVC。

上游删除约 2500 行旧设置宿主代码前，先确认本分支两套宿主中新增功能的消息、配置与事件都已迁入实际使用的 Settings 路径。仍有有效调用的扩展保留；完成调用链和合同回归后再删除死代码。

## 实施顺序与验收

| 阶段 | 交付 | 开始前依赖 | 验收重点 |
|---|---|---|---|
| P0 配置与输入保护 | 升级保留、凭据迁移、关键吞字及分页修复、运行时能力合同、更新身份与频道纠正 | 用户确认本规划 | 原配置与记录完整；新旧 DLL 和 Server 组合可输入；密码框无上下文请求；更新不指向错误产品 |
| P1 输入质量与词库 | 全拼、简拼、模糊音及日语修复，三语和五笔按键基础，11 库、全义项释义、打分优化 | P0 合同和迁移稳定 | 词库原始条数一致；每软件隔离；关闭仅移除本来源；读音和选词消耗正确 |
| P2 本地模型与 AI 任务 | 模型管理、P2C 适配、补全、问字、模板扩充 | 结果类型和焦点失效机制完成 | 模型缺失或失败可打字；用户选择才上屏；翻页后不跳回；模板回导无损 |
| P3 界面与可选功能 | fit_content、工具栏、热力图、Vim、皮肤、帮助及厂商控件；回归三语、五笔等新增设置 | 不重置原布局及开关 | 深浅主题、键盘操作、125% 与其他 DPI、双屏放置；新装与升级分别检查 |
| P4 构建与发行 | 固定词库输入、依赖、更新身份、安装包与验证清单 | 所有必选功能通过回归 | 干净重建；实际安装目录与产物一致；升级保留；源码和包摘要对应；Release 如实注明限制 |

功能验收包括 x64/x86 TSF 宿主、EDIT/RichEdit、浏览器、记事本、Word/WPS、微信、QQ、企业微信、钉钉、飞书及按规则关闭候选的终端或编辑器。敏感字段测试另含同步读取拒绝、无 InputScope 声明、旧 DLL、迟回请求及焦点切换，不能只测试正确声明密码的输入框。管理员窗口与多屏 DPI 属单独环境条件，未验证不得写成已通过。

输入样例至少包含 `nihao` 选前缀后标点、`kandy`、`gaizenmb`、`ywen`、`sshang`、`yibananzhao`、`zaijinuta` 选“再”后继续输入、模糊音 `min` 与 `lin`、日语 `hashi`/`rennai`。发布后纯简拼修复另测 `nbn`、`nqn`，同时保持 `bng` 的纠错选项。

词库验收覆盖 132,916 条的转换和摘要、11 库开关热更新、全拼及双拼召回、跨来源去重、个人翻译优先、完整义项导出回导、应用词库选择与学习记录分别保留。关闭专业库后仍出现基础同词是预期行为。

模型和网络验收区分合同夹具与真实推理。只使用已有模型或用户主动下载的模型；本轮及后续自动验证不擅自下载其他权重。完全离线模式测试零外网请求；本机文本服务须确认为回环地址。字幕、OCR、语音流式链路和原有模型切换也需回归，避免凭据和设置重构影响现有功能。

用户已确认 P0–P4 并授权实施、测试与个人仓库发行。版本为 0.10.2；本规划保留评审时的需求和验收范围，当前实施、安装与测试证据以[实施记录](implementation-progress.md)为准。没有执行的云服务、模型质量及特定实机环境不得按已通过处理。
