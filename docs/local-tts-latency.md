# 本地发音延迟验证

## 0.9.14：真实生成、传输和播放流

2026-10-11，在同一台 Windows / RTX 3060 Laptop 6 GB 上验证。新增模型权重仅下载用户明确要求的 MOSS-TTS-Nano；原有 Qwen 0.6B、Kokoro 继续复用。安装包不含模型权重，不自动下载其他模型。

- 内置适配器复用 `StreamingSynthesizer` 回调、PCM 分帧和原生 `waveOut` 播放器；生成期间立即传输和播放，流尾缺失视为失败。协议唯一来源为 `engine/contracts/tts_stream.json`，C++ 头由 `scripts/sync-tts-contract.py` 生成。传统客户端仍可请求完整 WAV。
- Qwen 检测 NVIDIA 驱动后使用配套 CUDA 12.8 的 torch / torchaudio 2.9.1，经 faster-qwen3-tts 0.5.4 的 CUDA graphs 逐块生成。加载时预热，再显示就绪。CPU 适配器也从增量 codec 输出解码，不是拆分最终 WAV。
- Kokoro 使用 sherpa-onnx 的生成回调，按段输出；单个短词仍需完成内部推理。1/2/4 线程对比后选用本机略快的 2 线程，保留有界内存缓存。
- MOSS 使用官方 ONNX CPU 模型及流式音频解码器，下载共 **717,153,306 字节**，逐文件固定 revision / SHA-256。运行包含内置音色，不含录音克隆编码器。默认中文 Xiaoyu、英文 Bella；给短词补句尾，修复无标点短文本偶发长停顿或重复。
- Edge-TTS 是在线服务客户端，不是离线模型。显式启用后将文本发送到微软；MP3 网络包即时解码并接入同一 PCM 播放链。固定公开测试句成功，首段生成约 1.225 秒，原离线配置未改变。

### 实测口径

“首段”从提交合成请求开始计时，不含首次依赖下载、模型加载及预热，也不是扬声器实际声压出现的精确时间。每组生成测试为三次不命中缓存的请求。

| 条件 | 首段生成范围 | 整段生成范围 |
|---|---:|---:|
| Qwen CUDA，“你好” | 467–514 ms | 1.00–1.35 s |
| Qwen CUDA，短句 | 406–446 ms | 1.64–2.18 s |
| Qwen CUDA，长句 | 398–460 ms | 4.05–4.52 s |
| MOSS CPU，“你好” | 399–464 ms | 0.81–1.03 s |
| MOSS CPU，短句 | 364–409 ms | 2.37–2.77 s |
| MOSS CPU，长句 | 375–453 ms | 4.39–4.57 s |

打包后的运行组件及正式 PCM 解析器 / 播放器经真实 Windows 音频设备播放长句：Qwen 首段入队 **517 ms**，MOSS **508 ms**；Kokoro **4.70 s**，完整传输约 **13.80 s**。首段播放不再等整段生成完成，但不同文本、负载和音色仍有差异。Qwen 第一次加载及 CUDA 预热约 56 秒，发生在“正在启动”阶段。

Kokoro 单词线程对比（每格 3 次，均值 ± 标准差）：4 线程中文 2629±115 ms、英文 1024±63 ms；2 线程中文 2475±35 ms、英文 954±92 ms；1 线程中文 2905±100 ms、英文 1055±5 ms。改善有限，不能替代 Windows 本机语音的即时响应。

首段播放 100 ms 后取消，Qwen 和 MOSS 均中断传输和播放。模型切换覆盖 Qwen → MOSS → Kokoro、加载中的 Qwen 被 MOSS 取代、停止后释放服务槽位、恢复 Qwen；测试过程配置文件摘要不变。独立离线 ASR 复核了中文长句及短词；“水杉”可能转写为同音“水山”，没有漏句或重复拼接。

Voxtral TTS 和 2026 论文版 ASLP-lab/FlashTTS 提供官方说明及部署入口，尚未内置一键运行适配器或验证本机性能。Voxtral 权重为 CC BY-NC 4.0。Dual-Track 是现有 Qwen3-TTS 架构说明，不另造同名模型项，也不宣传“全开源模型最低首包”。

## 故障修复

旧 Qwen 环境实际安装了 torch 2.9.1 和 torchaudio 2.11.0，导入扩展时出现 `torch_library_impl` 入口不存在。按 [PyTorch 官方配套表](https://docs.pytorch.org/audio/stable/installation.html) 固定二者为 2.9.1，两个 Qwen worker 均在加载原生 DLL 前检查依赖版本。修复现有环境后，模型导入与 0.6B CustomVoice 合成都成功。

打包后的隔离 worker 也通过测试：CPU 合成“你好”返回 24 kHz、PCM16、57,644 字节 WAV；第一次 HTTP 请求 9.886 秒，第二次命中内存缓存 0.0023 秒，返回字节完全一致。这是合成/传输耗时，不包含播放器启动、声卡缓冲和音频播放时长。未验证 GPU 或 1.7B 的速度。

## Kokoro 基线与缓存

通过 cProfile 分析已经加载的 INT8 CPU 模型，使用相同中文“你好”和英文“hello”，每种连续调用 3 次。缓存前总耗时 18.837 秒，17.619 秒消耗在 sherpa-onnx 的原生 generate 中。各次耗时如下（秒）：

| 条件 | 中文 1 / 2 / 3 | 英文 1 / 2 / 3 |
|---|---|---|
| 无缓存 | 5.499 / 4.243 / 3.519 | 3.058 / 1.242 / 1.275 |
| 加入缓存 | 2.961 / <0.001 / <0.001 | 1.173 / <0.001 / <0.001 |

缓存前后首轮差异含进程预热和系统负载差异，不能归因为模型推理提速；缓存只消除重复推理。函数内部的缓存命中时间不等于用户听到声音的端到端延迟。

缓存最多 128 条、16 MiB；文字、音色、语言或速度变化会重新合成，超出容量按最近使用顺序淘汰。异常和超过容量的音频不缓存。缓存只存在于服务进程内，重启或换模型后释放，不创建音频历史文件。
